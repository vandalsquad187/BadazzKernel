2.  GIT-VERSION-ERKENNUNG IN KBUILD (GEFIXT)
--------------------------------------------------------------------------------
PROBLEM:
  drivers/kernelsu/Kbuild versucht KSU-Version per git rev-list --count HEAD
  zu ermitteln. Die Logik prüft ob KSU ein SEPARATES Git-Repo ist (Submodule):
    GIT_ROOT == KERNEL_GIT_ROOT → Version NICHT setzen
  Da KSU per setup.sh in den Kernel-Tree kopiert und committet wurde, sind
  GIT_ROOT und KERNEL_GIT_ROOT identisch → Fallback auf v0.0.1 / KSU_VERSION=1.
  Der Manager zeigt dann "Unsupported / not integrated / version too low".

FIX (drivers/kernelsu/Kbuild):
  - Git-Detection-Block entfernt (78 Zeilen → 12 Zeilen)
  - Version hardcoded:
      KSU_GIT_VERSION := 33131
      KSU_GIT_TAG := v3.1.0-legacy
      KSU_GIT_VERSION_VALID := 1
  - Manager sieht nun KSU_VERSION=63131, Tag=v3.1.0-legacy → "Supported"

3.  TIF_SECCOMP – UNSUPPORTED IM MANAGER (GEFIXT)
--------------------------------------------------------------------------------
ROOT CAUSE:
  Der Manager prüft ob TIF_SECCOMP thread flag gesetzt ist.
  In kernel/fork.c, copy_seccomp() ab Zeile 1500:
    if (p->seccomp.mode != SECCOMP_MODE_DISABLED)
        set_tsk_thread_flag(p, TIF_SECCOMP);
  NEU geforkte Kind-Prozesse erben das Flag ZWANGSWEISE zurückgesetzt,
  auch wenn der Parent es vorher gecleart hatte.

FIX 1: trace_sched_process_fork (setuid_hook.c)
  - Registriert Handler auf trace_sched_process_fork
  - Feuert in _do_fork() NACH copy_seccomp() aber VOR wake_up_new_task()
  - Child existiert bereits, hat gültigen task_struct – läuft aber noch nicht
  - Handler: if (parent->cred->uid.val >= 10000)
                 clear_ti_thread_flag(task_thread_info(child), TIF_SECCOMP);

FIX 2: for_each_thread in ksu_handle_setresuid() + setresuid_ret_handler
  - Statt nur clear_thread_flag(TIF_SECCOMP) auf current:
      rcu_read_lock();
      for_each_thread(current, p)
          clear_ti_thread_flag(task_thread_info(p), TIF_SECCOMP);
      rcu_read_unlock();
  - Erfasst ALLE Threads des Prozesses, nicht nur current

4.  __SECURE_COMPUTING KPROBE – ENTFERNT (crasht auf arm64)
--------------------------------------------------------------------------------
PROBLEM:
  secure_comp_bypass_pre_handler manipulierte regs->regs[0] = 0
  (setzt Fehler-Code auf 0). Auf arm64 ist PC-Manipulation via pre_handler
  mit Seiteneffekten → Gray Screen + Reboot.

FIX: Komplett entfernt (kprobe + handler + registration/unregistration).
  Wird nicht mehr benötigt – der trace_sched_process_fork Ansatz + Seccomp
  Cache sind sicherer.
